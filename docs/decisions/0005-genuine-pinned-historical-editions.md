# Genuine historical editions from retained OLRC archives

Status: accepted implementation scope; source, publication and deployment acceptance remain separate.

Historical availability requires independently acquired publisher bytes, not a constructed XML literal or an asserted cache review flag. Retain the pinned Title 18 ZIPs for PL 119-73 and PL 119-142 with their original versioned URLs, acquisition observation, archive SHA-256, exact member name and SHA-256, namespace and publisher edition identity. Archive raw inputs in GitHub release assets and a verified local cache; bulk archives and complete XML members stay off Pages.

The bounded pilot covers sections 1001, 111 and 1114 in each edition. Qualification compares production Markdown and sanitized rendered HTML against the independently parsed original full member using the existing text-lane and parent/list-placement oracle. Tables, footnotes, unknown source structures or any witness mismatch fail closed. Whole-title inventory, legacy navigation records and the six-unit verified pilot have separate denominators. Matching selected text between two snapshots establishes no amending act, enactment date or legal-applicability claim.

A reviewed qualification manifest pins each source section, Markdown and rendered-fragment digest together with the source-member and compiler/renderer/oracle recipe. A provision version receives a fresh identity derived from those inputs. The four withdrawn constructed version IDs, source IDs, assertion IDs and event IDs remain withdrawn. Genuine-source cache replay must match the reviewed materialization pins; changing a review flag or reproducing an artifact SHA alone cannot confer publisher provenance. Recipe drift produces an unqualified candidate until the full source oracle is rerun and the reviewed pins are updated.

The catalog carries optional typed source qualification with genuine versions; legacy versions retain their explicit legacy-derived status. Source-generated claims are limited to witnessed source content and literal same-edition references. The pilot does not create legal-amendment, effective-date or substantive authority claims. Old constructed production inputs move to test-only fixtures, while already-retained raw objects, Git tags and correction history remain addressable.

Expose only bounded section shards, qualification manifests and sanitized rendered fragments on Pages. Genuine shard URLs use `/history/{releaseId}/{uscTitle}/{uscSection}/` with exact release/title/section identity, independent of the current corpus's chapter or publication. The static reader performs source/materialization-pin checks at build time and renders the same fragment qualified by the source oracle. Cold and JavaScript-disabled requests therefore return the selected witnessed edition or an explicit gap. Legacy query URLs do not silently substitute current law. Existing consumers accept the new route only with the explicit qualified-source contract; legacy navigation remains separately labeled.

Source-cache export/import is deterministic, bounded and verifies every member before adoption. GitHub archival uses new content-addressed names and binary readback, never replacement of an existing asset/tag. Recovery after complete local cache loss must reconstruct the same semantic catalog and public shards using pinned source and recipe inputs. Operational generation and acquisition observations remain distinct from publication/enactment dates and are not inferred from Git timestamps.

Verification includes two cold offline replays, missing/corrupt archive and member inputs, cache-proof mutation, inserted note/reference/table mutations, byte-identical outputs, six genuine full-member oracle checks, legacy positive controls, scoped exports and same-edition navigation. Final acceptance requires real-diff independent review, all local/hosted checks, static build, blocked-external and JavaScript-disabled readers, protected source publication and public readback. Canonical/current corpus corrections remain owned by the separate source-correction workflow.
